# 0006. アプリアイコンの意匠決定とグリフ実装のフォント依存リスク

## ステータス

Accepted

## 背景

マイルストーン5（`.deb`パッケージング化）に向けて、`.desktop`の`Icon=`・ファイルマネージャー/ランチャー表示用のアプリアイコンが必要になった。これまでアイコン資産は存在しなかった。

Easy Archiveの核心価値（文字コード自動判定）を一目で伝えるため、モチーフを「文字化け→正しい日本語」、配色を「オレンジ系（親しみやすさ）」とし、3案（フォルダ案／分割案／ZIPバッジ案）を作成して比較検討した。比較用の一覧はArtifactとして作成し、目視で候補3「ZIPバッジ案」（ジッパー付きの箱＋「あ」の丸バッジ）を採用と決定した（候補1「フォルダ案」はIME切り替えアイコンに見えるとの指摘があり除外）。

## 決定

- 採用案は候補3「ZIPバッジ案」。`packaging/icons/easy-archive.svg`に配置し、将来`.desktop`の`Icon=easy-archive`、`/usr/share/icons/hicolor/scalable/apps/easy-archive.svg`としての配置を想定する。
- バッジ内の「あ」はSVGの`<text>`要素で描画し、`font-family`のフォールバックとして`'Noto Sans JP','Zen Maru Gothic',sans-serif`を指定する。文字を手描きのベクターパスに置き換える案も検討したが、この開発環境にはSVGラスタライズ/ブラウザ描画ツール（`rsvg-convert`/`cairosvg`/Chromium等）が一つも無く、自己検証なしで手描き字形を確定すると「あ」に見えない字形を本番に混入させるリスクの方が高いと判断し、見送った。
- 開発機では`fc-list`で`Noto Sans CJK JP`の搭載を確認済み。対象OS（Ubuntu/Zorin OS、日本語ロケール前提の学校・自治体PC）でも標準的に日本語フォントが搭載されている可能性が高いと判断し、フォント依存を許容する。

## 既知の限界

- `<text>`によるグリフ描画は、対象システムに日本語対応フォントが無い場合、代替グリフ（トーフ／□）で表示される可能性がある。実機（Zorin OS等）でのレンダリング確認はまだ行っていない。ADR 0004／0005と同様、実機検証待ちとして扱う。
- SVGラスタライズツールが無いため、PNGフォールバックは未作成。当面は`.desktop`／`hicolor`テーマともにSVG単体での配布を前提とする。PNGが必要になった場合は別途`rsvg-convert`等の導入を検討する。

## 影響

- `packaging/icons/easy-archive.svg`を新規追加した。
- `README.md`にロゴとして表示を追加した。
- `.desktop`ファイル・`cargo-deb`への組み込みなど、`.deb`パッケージング本体の実装はまだ着手していない（別途対応）。
