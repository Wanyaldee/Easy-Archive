# Easy Archive コア設計方針

## 文字コード判定はエントリ単位

`rc-zip`クレートを技術検証した結果、アーカイブ全体で1回だけ文字コード判定を行う設計（`chardetng`に全非UTF8エントリの名前をまとめてfeedし、1つの`Encoding`を全エントリに一律適用）だと判明した。これでは1つのZIPに複数言語のファイル名が混在した場合に破綻する。

→ **必ずエントリ（ファイル名）ごとに個別判定する。** アーカイブ全体でまとめて判定するコードを書かない。詳細な調査経緯は [ADR 0001](../../../docs/adr/0001-zip-crate-over-rc-zip.md)を参照。

## ZIP読み書きは `zip` クレートに統一

- `rc-zip`は読み取り専用のため不採用。`zip`クレート（MIT）で読み書き両方を行う。
- ファイル名は `ZipFile::name_raw()` で生バイト列として取得し、GPBのUTF-8フラグが立っていなければ`encoding_rs`でShift-JISとしてデコードを試みる。エラーなく成功すればShift-JIS、失敗すればCP437として扱う（`src/encoding.rs`の`decode_entry_name`参照）。
- `chardetng`による統計的判定は不採用。ファイル名程度の短いバイト列では信頼性が低く、実装時のテストで半角カナ入りShift-JISファイル名をBig5と誤判定することが判明した（[ADR 0002](../../../docs/adr/0002-drop-chardetng-strict-decode.md)を参照）。
- 圧縮時のファイル名エンコーディングは既定でUTF-8（汎用フラグbit11セット）。Shift-JIS等での圧縮出力は対象外。

## スコープ境界

- 対応フォーマットは当面ZIPのみ。tar.gz等を追加しない。
- 第一段階の対象OSはUbuntu系（Zorin OS含む）のみ。
- 「文字コード解析」はファイル名/パスのデコードのみが対象。ZIP内のファイルの中身（Office/バイナリ）はバイト列のまま無変換で読み書きする。中身の変換ロジックを実装しない。

## 言語方針

ドキュメント・コメント・コミットメッセージ・Issue/PRは日本語。コード識別子（関数名・変数名）はRustの慣習に従い英語。
